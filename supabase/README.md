# 10Qadam: подключение онлайна

Соло и явно отмеченное демо с ботами работают без аккаунта и Supabase. Онлайн требует реального проекта Supabase. В дуэли нужны два одновременно подключённых аккаунта, в баттле — четыре.

## Supabase

1. Создайте проект в Supabase. Откройте **SQL Editor → New query**, вставьте весь `supabase/schema.sql` и выполните его. Повторное выполнение безопасно для существующих данных; не меняйте типы уже существующих таблиц этим файлом.
2. В **Project Settings → API** скопируйте URL проекта и публичный `anon` key (либо новый publishable key). Не используйте `service_role` или secret key на сайте.
3. Создайте в корне `.env.local`:

   ```env
   VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
   VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY
   ```

4. В **Authentication → URL Configuration** задайте Site URL опубликованного сайта. Добавьте `http://127.0.0.1:5173` и точный HTTPS-адрес Vercel в Redirect URLs. Если порт локального сервера другой, добавьте и его.
5. В **Authentication → Providers → Email** включите вход по email. При включённом подтверждении email игроку необходимо открыть письмо до первого входа. Для надёжной доставки настоящим пользователям настройте SMTP; встроенная почта Supabase имеет ограничения.
6. Для Google создайте OAuth-клиент в Google Cloud, добавьте показанный Supabase callback URL в Authorized redirect URIs, включите Google в Supabase и укажите Client ID/Secret **только там**. Добавьте свой домен и тестовые аккаунты согласно настройкам OAuth consent screen Google. После настройки задайте `VITE_AUTH_GOOGLE=true` локально и в Vercel; до этого кнопка Google скрыта.
7. Перезапустите локальный сервер после изменения `.env.local`.

## Vercel

Для уже работающей базы сначала выполните целиком `supabase/migrations/20261014_ranked_levels.sql`, затем публикуйте новый клиент. Миграция добавляет B1/B2/C1 без сброса старых рейтингов, комнат, ответов и очередей; повторное выполнение безопасно. Новый проект устанавливается сразу из обновлённого `schema.sql`. Генератор `node scripts/ranked-levels.mjs` поддерживает одинаковые версии схемы и миграции.

1. Загрузите проект в собственный GitHub-репозиторий и импортируйте его в Vercel.
2. Framework: **Vite**, Build command: `npm run build`, Output directory: `dist`.
3. Добавьте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` в Environment Variables для Production. Для Preview используйте отдельный проект/настройки, если не хотите общего рейтинга с основной версией.
4. Опубликуйте сайт, внесите полученный HTTPS-адрес в Supabase Site URL и Redirect URLs и сделайте новый deployment после изменения переменных.
5. Проверьте регистрацию, подтверждение email, вход Google и матч из двух независимых браузерных сессий. Не храните пароли, приватные ключи или `.env.local` в Git.

## Механика и ограничения MVP

### Предложения и ИИ-планы

Для существующего проекта после ranked-levels примените `supabase/migrations/20261014_sentence_battles.sql`, затем `supabase/migrations/20261014_ai_plan_quota.sql`. Новая установка из `schema.sql` уже включает оба блока. Старые комнаты и словесные рейтинги сохраняются. Повторные миграции не сбрасывают данные.

Предложения A1–C1: 60 оригинальных заданий, пять общих раундов по 35 секунд, отдельные Elo `rating_sentence_*`, очереди не смешивают форматы. Ответ до 500 символов проверяется сервером. Регистр, пунктуация и лишние пробелы не снижают точность; победа определяется суммой точности по пяти раундам, при равенстве — ничья без преимущества за скорость.

Для Gemini используется только серверная переменная `GEMINI_API_KEY` в Vercel. Приватная таблица квоты и `consume_plan_quota()` ограничивают генерацию атомарно: 3 попытки на пользователя и 100 на проект за UTC-сутки; запросы Google оплачиваются/лимитируются согласно настройкам владельца. Публичный ключ Supabase и JWT проверяют пользователя; service-role ключ на клиенте не нужен. Подробности: `docs/ai-plan.md`.

- Одинаковый режим и уровень; очередь начинает искать в диапазоне ±100 Elo, расширяется на 75 каждые 10 секунд, максимум ±600. Начальный рейтинг — 1000 отдельно для A1, A2, B1, B2 и C1. Соло рейтинг не меняет.
- 10 слов по 12 секунд, отсчёт 3 секунды. Все игроки получают одни и те же слова. Сервер принимает один ответ за раунд, проверяет его и время; правильный ответ даёт 100 очков плюс до 50 за скорость. Места определяются сначала числом правильных ответов, затем очками за скорость.
- PostgreSQL определяет соперников, время, очки и Elo. Клиент не может записывать очки, рейтинг, чужие ответы или читать будущие слова напрямую. Матчи завершаются идемпотентно: повторный запрос не начисляет рейтинг дважды. Выход до окончания матча оставляет игрока участником; пропущенные слова дают ноль.
- Состояние синхронизируется коротким опросом RPC; отдельная настройка Supabase Realtime для запуска не нужна. Удалённая или закрытая вкладка исчезает из очереди через 30 секунд без опроса.
- Браузер произносит текущее слово через speech synthesis. Поэтому текст текущего слова доступен в сетевом ответе, и автоматизация может его прочитать. Серверная проверка защищает данные, **но полноценного античита здесь нет**. Для соревнований с призами потребуется аудио, выдаваемое сервером без текста ответа, и дополнительные ограничения запросов.
- При отключении всех участников итог сохраняется после следующего вызова `finish_match` либо перед их следующим поиском игры; для немедленного завершения покинутых комнат в продакшене добавьте серверную задачу. Сайт не требует постоянного процесса Vercel.
- Словарь A1/A2 — прежняя стартовая подборка. B1/B2/C1 содержат 5 299 одиночных слов из CEFR-J/Octanove (2 058 / 2 364 / 877); это учебный ориентир, не официальная экзаменационная классификация. Редактируйте его в SQL Editor, не открывая публичные права на таблицу `words`.

## Проверка перед публичным запуском

У двух новых аккаунтов рейтинг должен быть 1000; ни один из уровней A1–C1 не смешивается с другими; повторный ответ на тот же раунд отклоняется; ответ после 12 секунд отклоняется; нельзя читать чужой матч; повторная финализация не меняет рейтинг; прямой UPDATE profiles из браузера запрещён. Нулевой матч должен завершаться ничьей без роста рейтинга.

Google индексирует открытую главную страницу. После публикации добавьте сайт как ресурс с префиксом URL в Search Console, подтвердите владение HTML-тегом и запросите индексацию. Бесплатный Vercel Hobby предназначен для личного некоммерческого использования; перед рекламой или продажами проверьте актуальные условия тарифа.
